# Birthday event project

The fork currently contains the original GeoGuess application; the birthday-event behavior described here is **planned, not implemented**. Baseline development work has begun; see the [development and smoke-test guide](development-baseline.md).

1. [Requirements and acceptance criteria](event-requirements.md) — **source of truth** for what the event must do.
2. [Fork baseline and gap analysis](current-state-gap-analysis.md) — what existing code already provides and what needs verification or change.
3. [Prioritized implementation roadmap](implementation-roadmap.md) — order of delivery and definition of done.
4. [GitHub Issues](https://github.com/bottybotson/GeoGuess/issues) — active task tracking and acceptance checklists (#1–#9); [backlog index](backlog.md) keeps the work items mapped to requirements.

Planning maximum: **50 players**, not expected attendance. First round: an easy, slow tutorial; choosing the event venue is optional. The host must be able to adjust round duration **while the game runs**. Prefer separate host/admin and read-only spectator presentation pages. Personal imagery after guesses is low priority.
